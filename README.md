# Запрет (EXP) — Android-приложение, перенос стратегии `general (EXP).bat` с ПК

APK: **`app/dist/Zapret-EXP.apk`** (≈58 КБ, `ru.zapret.exp`, подпись `CN=Zapret EXP`).

Приложение поднимает локальный туннель (`VpnService`) и применяет к трафику те же приёмы
десинхронизации DPI, что на ПК делает `bin\winws.exe` из папки
`C:\Users\Admin\OneDrive\Desktop\zapret-discord-youtube-1.10.4` по кнопке
`general (EXP).bat`. Один тумблер = «запрет включён», второй = выключено.
Ничего не шифруется, туннель локальный, на чужие серверы трафик не уходит.

## Как собрать (0 МБ закачек)

```bash
bash run_tests.sh                    # 67 проверок ядра и конфига на обычной JVM
bash app/build.sh Zapret-EXP         # aapt2 -> javac -> d8 -> zipalign -> apksigner
```

Используются только то, что уже стоит на машине:
`D:\Утилиты\AndroidBuildTools\jdk\jdk-17.0.20.1+1`,
`D:\Утилиты\AndroidBuildTools\sdk\platforms\android-34`, `build-tools\34.0.0`.
Ни Gradle, ни NDK, ни CMake не нужны: приложение целиком на Java, native-кода нет.

Сборка идёт в ASCII- staging `D:\zapret-build\` (aapt2 в Windows не читает кириллические
пути в аргументах), готовый APK копируется в `app/dist/`. Копия ключа подписи после
подписи из staging удаляется скриптом.

Ключ подписи: `keys\zapret-exp.keystore`, alias `zapret-exp`, пароль `zapret-exp`.
**Не теряй его**: без него следующее обновление APK не встанет поверх этого.

## Как пользоваться на телефоне

1. Перенести `Zapret-EXP.apk` (Tecno Spark 40 Pro — arm64).
2. Установить (разрешить «неизвестные источники»).
3. Открыть → включить тумблер → система спросит «Разрешить приложение **Запрет (EXP)**
   создавать постоянное VPN-соединение» → **Разрешить** (можно сразу отметить
   «Использовать всегда», тогда туннель поднимется после перезагрузки сам).
4. В приложении видно: счётчики TCP/UDP-потоков, сколько раз применён десинк (TLS/HTTP/QUIC),
   сколько трафика прошло, и журнал вида:
   `десинк [general-main] tls 142.250.x.x:443 (www.googlevideo.com) фрагменты=[1, 3, 5, 7]`,
   `udp-fake [quic-general] x11 ttl=8 -> 162.159.x.x:443`.
   Эти строки — доказательство, что стратегия реально работает, а не «включилось и молчит».
5. Проверить: видео YouTube, созвон/видео в Discord. Выключить тумблер — должно снова
   вести себя как без приложения.

## Что перенесено из твоей папки 1-в-1

`app/assets/pc/` → внутри APK:
- `zapret-general.txt` ← `lists/list-general.txt` + `list-general-user.txt` (Discord,
  Cloudflare, DoH-серверы),
- `zapret-google.txt` ← `lists/list-google.txt` (YouTube/googlevideo/ytimg/play),
- `zapret-exclude.txt` ← `lists/list-exclude.txt` + `list-exclude-user.txt` (Twitch, Steam, …),
- `discordmedia.txt` ← `--hostlist-domains=discord.media`,
- `tls_clienthello_www_sferum_ru.bin`, `tls_clienthello_www_google_com.bin`,
  `quic_initial_www_google_com.bin`, `stun2.bin`, `ACTIVE_DISCORD_UDP.bin` ← `bin/`
  (те же байты фейков),
- `general-EXP.ref.bat` — исходный bat для сверки.

Правила: `app/assets/rules-exp.txt` (текстовый, читается глазом; можно править значения
`repeat/ttl/split` и пересобирать).

## Структура кода

| Файл | Что делает |
|---|---|
| `Bits.java` | ручной разбор/сборка IPv4/IPv6 + TCP/UDP, контрольные суммы |
| `Hello.java` | TLS ClientHello → SNI, HTTP → Host, DNS → имя запроса и адреса ответов |
| `Splits.java` | точки фрагментации запроса (перенос `split-pos`/`repeats`/`seqovl`) |
| `Config.java` | синтаксис списков zapret (`^домен`, поддомены) и парсинг правил — чистый, тестируется на JVM |
| `Profile.java` | загрузка списков/фейков/правил из APK, подбор правила, карта IP→домен из DNS |
| `Desync.java` | сама десинхронизация: фрагментация TCP, фейки, TTL |
| `TcpFlow.java` | конечная точка TCP в пользовательском пространстве + релей |
| `UdpFlow.java` | релей UDP/DNS/QUIC |
| `ZapretService.java` | туннель `VpnService`, маршрутизация пакетов, счётчики, уведомление |
| `MainActivity.java` | экран с одним тумблером и журналом |

## Что работает иначе, чем на ПК (важно знать)

Android без root не даёт трогать номера последовательности, TCP Timestamp и вставлять
байты в чужой поток — на ПК это делает WinDivert. Поэтому:

1. **TCP**: применяются только сохраняющие поток приёмы — фрагментация ClientHello
   (позиции из правила + разделение заголовка TLS-записи) и `TCP_NODELAY`.
   Фейковый ClientHello уходит **отдельным соединением с малым TTL**, а не врезается в
   наш поток: иначе сервер получил бы мусор вместо начала handshake и TLS бы умер.
2. **QUIC/UDP**: здесь приём перенесён точно — дополнительные датаграммы с фейковым
   QUIC Initial из твоего `quic_initial_www_google_com.bin` (`repeat=11`, `ttl=8`),
   плюс `ACTIVE_DISCORD_UDP.bin` для диапазонов 19294-19344/50000-50100. Датаграммы
   независимы, поэтому поток не портится.
3. `--dpi-desync-fooling=ts` заменён TTL фейка (тот же смысл: DPI видит, сервер — нет).
4. `--dpi-desync-repeats=4/8` → 4/8 точек разбиения, `seqovl` в точном виде отсутствует.
5. Блоки 6-9 твоего bat завязаны на `ipset-all.txt`, где сейчас одна заглушка
   `203.0.113.113/32`, то есть на ПК они не обрабатывают ничего. Вместо них — правило
   `quic-general` по адресам из списков; «всё остальное» выключено по умолчанию
   (`quic-any` закомментирован, есть и вариант `quic-block` для отбрасывания QUIC).
6. Групповые адреса (224.0.0.0/4, ff00::/12) и broadcast не релелятся — пока тумблер
   включён, Chromecast/локальная сеть по mDNS может не находиться. Это нормальное
   поведение любого rootless VPN.
7. DNS-серверы не подменяются: запросы идут туда же, куда слала система (то есть
   поведение как у zapret на ПК, который адрес DNS тоже не трогает).

## Проверено / не проверено

- Проверено автоматикой: разбор и сборка пакетов, контрольные суммы IPv4/TCP/UDP,
  round-trip данных, SNI из твоих же `.bin` (в т. ч. подмена при совпадении длины),
  HTTP Host, DNS A/AAAA, инвариант «фрагментация не теряет и не дублирует байты» для
  длин 1..1500, весь конфиг из APK (5 правил, все fake-файлы на месте, совпадения
  правил для discord.com / www.googlevideo.com / twitch.tv / discord.media / UDP 19300).
  Итог: `пройдено: 67, провалено: 0`.
- **Не проверено на живом телефоне** — устройства подключённого к ПК нет (`adb` не
  устанавливал, закачку не делал). Это единственный шаг, который может сказать «работает
  или нет» в твоей сети. Если что-то из пунктов не заведётся, нужны строки из журнала в
  приложении — по ним правится конкретное правило (`ttl`, `repeat`, `split`), а не всё сразу.
